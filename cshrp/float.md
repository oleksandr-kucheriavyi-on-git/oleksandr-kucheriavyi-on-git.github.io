Типи даних `float` (`System.Single`) та `double` (`System.Double`) у C# реалізовані відповідно до міжнародного стандарту **IEEE 754** (стандарт для арифметики з плаваючою комою).

Через специфіку представлення дробів у комп'ютерній пам'яті, ці типи мають спеціальні архітектурні значення для обробки виняткових ситуацій (наприклад, ділення на нуль або неможливих математичних операцій). На відміну від цілих чисел (`int`), які при діленні на `0` викидають помилку `DivideByZeroException`, `float` та `double` ніколи не викидають помилок, а натомість повертають ці спеціальні значення.

Ось усі спеціальні значення, які існують у C#:

---

## 1. NaN (Not a Number — Не число)

Це значення виникає, коли результат математичної операції є невизначеним або не має сенсу.

* **Як отримати:** * Ділення нуля на нуль: `0.0 / 0.0`
* Ділення нескінченності на нескінченність: `double.PositiveInfinity / double.PositiveInfinity`
* Множення нуля на нескінченність: `0.0 * double.PositiveInfinity`
* Корінь з від'ємного числа: `Math.Sqrt(-1.0)`


* **Константи в C#:** `float.NaN` та `double.NaN`

### Головна підступність NaN:

`NaN` не дорівнює **нічому**, навіть самому собі!

```csharp
double x = 0.0 / 0.0; // x є NaN

Console.WriteLine(x == double.NaN); // Виведе False!
Console.WriteLine(x == x);          // Виведе False!

```

> **Як правильно перевіряти:** Щоб дізнатися, чи є число `NaN`, завжди використовуйте спеціальний метод: `double.IsNaN(x)` або `float.IsNaN(x)`.

---

## 2. Positive Infinity (+∞ — Додатна нескінченність)

Це значення представляє число, яке є занадто великим (за модулем), щоб його можна було зберегти у виділеній кількості біт для `float` чи `double`.

* **Як отримати:** * Ділення додатного числа на нуль: `1.0 / 0.0`
* Переповнення типу (Overflow): наприклад, якщо помножити найбільше можливе число `double.MaxValue` на `2.0`.


* **Константи в C#:** `float.PositiveInfinity` та `double.PositiveInfinity`
* **Особливість:** Якщо додати будь-яке число до `PositiveInfinity`, результатом все одно буде `PositiveInfinity`.

---

## 3. Negative Infinity (-∞ — Від'ємна нескінченність)

Аналогічно до додатної, але представляє число, яке є занадто великим у від'ємну сторону.

* **Як отримати:**
* Ділення від'ємного числа на нуль: `-1.0 / 0.0`
* Множення від'ємного числа на додатну нескінченність.


* **Константи в C#:** `float.NegativeInfinity` та `double.NegativeInfinity`

> **Як перевіряти нескінченність:** Використовуйте методи `double.IsInfinity(x)` (для будь-якої нескінченності), `double.IsPositiveInfinity(x)` або `double.IsNegativeInfinity(x)`.

---

## 4. Від'ємний нуль (-0.0)

Оскільки стандарт IEEE 754 виділяє один окремий біт під знак числа (0 — плюс, 1 — мінус), у типах `float` та `double` технічно існує два нулі: `0.0` (додатний) та `-0.0` (від'ємний).

* **Як отримати:**
* Ділення нуля на від'ємне число: `0.0 / -5.0`
* Множення нуля на від'ємне число: `0.0 * -1.0`
* Ділення додатного числа на від'ємну нескінченність: `1.0 / double.NegativeInfinity`



### Важливі нюанси з `-0.0`:

* При звичайному порівнянні компілятор вважає їх рівними: `0.0 == -0.0` поверне `True`.
* Проте вони поводяться по-різному під час ділення. Наприклад, `1.0 / 0.0` дасть `+∞`, а `1.0 / -0.0` дасть `-∞`.

---

## Зведена таблиця констант у C#

Для зручності використання всі ці значення зашиті у властивості відповідних структур:

| Опис значення | Для типу `double` | Для типу `float` |
| --- | --- | --- |
| **Не число** | `double.NaN` | `float.NaN` |
| **+ Нескінченність** | `double.PositiveInfinity` | `float.PositiveInfinity` |
| **- Нескінченність** | `double.NegativeInfinity` | `float.NegativeInfinity` |
| **Максимальне число** | `double.MaxValue` (~$1.79 \times 10^{308}$) | `float.MaxValue` (~$3.4 \times 10^{38}$) |
| **Мінімальне (найближче до 0)** | `double.Epsilon` (~$4.9 \times 10^{-324}$) | `float.Epsilon` (~$1.4 \times 10^{-45}$) |



Робота з дійсними числами (типами з плаваючою комою) у програмуванні — це класична «мінна зона». Проблема не є специфічною лише для C#, вона криється в самому міжнародному стандарті **IEEE 754**, за яким комп'ютери обробляють типи `float` та `double`.

Давайте розберемося, чому виникають помилки округлення і чому звичайне порівняння через `==` може зламати логіку вашої програми.

---

## 1. Чому виникають помилки округлення?

Головна причина: **комп'ютер мислить у двійковій системі, а люди — у десятковій.**

У десятковій системі ми не можемо точно записати дріб $1/3$, ми пишемо $0.33333...$ і змушені десь зупинитися, через що втрачається точність. У двійковій системі числення (яку використовує процесор) неможливо точно представити більшість простих десяткових дробів, таких як $0.1$ або $0.2$. Для комп'ютера вони перетворюються на нескінченні періодичні дроби.

Оскільки пам'ять під `float` (32 біти) або `double` (64 біти) обмежена, комп'ютер просто "відрізає" хвіст цього нескінченного числа. Це призводить до **помилки представлення (representation error)**.

### Класичний приклад у C#:

Спробуйте виконати цей код:

```csharp
double a = 0.1;
double b = 0.2;
double sum = a + b;

Console.WriteLine(sum); 
// Ви очікуєте побачити 0.3, але C# виведе: 0.30000000000000004

```

Через те, що $0.1$ та $0.2$ були збережені з крихітною похибкою, при їх додаванні похибки накопичилися, і в результаті ми отримали зайву четвірку наприкінці 17-го знаку після коми.

---

## 2. Чому не можна порівнювати `float` та `double` через `==`?

Через вищеописані похибки округлення, математично правильні рівності в коді стають хибними.

Якщо продовжити попередній приклад:

```csharp
double a = 0.1;
double b = 0.2;

if (a + b == 0.3)
{
    Console.WriteLine("Вони рівні!");
}
else
{
    Console.WriteLine("О ні, вони НЕ рівні!"); // Спрацює ця гілка!
}

```

Компілятор порівнює `0.30000000000000004` та `0.30000000000000000`. Для процесора це абсолютно різні набори бітів, тому оператор `==` повертає `false`.

### Види помилок, що виникають при порівнянні:

1. **Втрата значущості (Underflow):** Коли результат операції стає настільки малим, що комп'ютер округлює його до абсолютного нуля. Порівняння з нулем може не спрацювати.
2. **Скасування (Cancellation):** Якщо відняти два дуже близьких за значенням великих числа, значущі розряди можуть знищитися, а «сміття» з кінця числа (похибка) вийде на перший план.
3. **Накопичення похибки в циклах:** Якщо ви додаєте `0.1` у циклі 10 разів, очікуючи отримати `1.0`, ви отримаєте щось на кшталт `0.9999999999999999`, і умова завершення циклу `while (x != 1.0)` перетвориться на нескінченний цикл.

---

## 3. Як правильно порівнювати дійсні числа?

Існує два основних способи вирішення цієї проблеми, залежно від вашої задачі.

### Спосіб 1: Порівняння з допуском (Epsilon) — для наукових/інженерних обчислень

Замість перевірки `a == b`, перевіряють, чи є різниця між числами настільки мізерною, що нею можна знехтувати. Цю допустиму похибку називають **епсилон ($\epsilon$)**.

```csharp
double a = 0.1 + 0.2;
double b = 0.3;

double epsilon = 0.00001; // Обираєте точність, яка вам потрібна

// Перевіряємо, чи модуль різниці менший за epsilon
if (Math.Abs(a - b) < epsilon)
{
    Console.WriteLine("Числа практично рівні з заданою точністю.");
}

```

Починаючи з .NET 6, для типу `double` з'явився готовий метод порівняння, який використовує адаптивний епсилон:

```csharp
if (double.Abs(a - b) < 1e-9) { ... }

```

### Спосіб 2: Використання типу `decimal` — для фінансів

Якщо ви працюєте з грошима (ціни, податки, баланси рахунків), типи `float` та `double` **суворо заборонено використовувати**. Замість них у C# є тип **`decimal`**.

* `decimal` зберігає числа у **десятковому** форматі (як $10^x$), а не двійковому.
* Він повністю позбавлений похибок на кшталт $0.1 + 0.2 = 0.30000000000000004$.
* Числа типу `decimal` **можна** безпечно порівнювати через `==`.

```csharp
decimal m1 = 0.1m;
decimal m2 = 0.2m;

if (m1 + m2 == 0.3m)
{
    Console.WriteLine("Для decimal вони завжди рівні!"); // Спрацює!
}

```

*Плата за це:* `decimal` працює у кілька разів повільніше на рівні процесора і займає 16 байтів пам'яті (замість 8 байтів у `double`).
