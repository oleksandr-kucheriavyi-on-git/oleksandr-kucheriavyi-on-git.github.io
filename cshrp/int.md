Типи даних `byte`, `sbyte` та `short` у C# належать до категорії **цілочисельних типів меншої розрядності** (integral types of smaller size). Головна їхня особливість полягає в тому, що CLR (Common Language Runtime) та процесор оптимізовані для роботи з 32-бітними (`int`) та 64-бітними (`long`) числами.

Через це робота з "малими" типами має низку специфічних нюансів, особливо в операціях.

---

## 1. Особливості типів даних

| Тип | Системний тип (.NET) | Розмір у пам'яті | Діапазон значень | Особливість знаку |
| --- | --- | --- | --- | --- |
| **`sbyte`** | `System.SByte` | 1 байт (8 біт) | від `-128` до `127` | Знаковий (Signed) |
| **`byte`** | `System.Byte` | 1 байт (8 біт) | від `0` до `255` | Беззнаковий (Unsigned) |
| **`short`** | `System.Int16` | 2 байти (16 біт) | від `-32 768` до `32 767` | Знаковий (Signed) |

### Ключові особливості:

* **Економія пам'яті:** Їх використовують переважно для оптимізації (наприклад, у великих масивах) або при роботі з бінарними файлами, мережевими протоколами та низькорівневими API.
* **Відсутність літералів:** Як уже згадувалося, для них немає власних суфіксів (як `m` для `decimal` чи `L` для `long`). Число `5` компілятор бачить як `int` і автоматично дозволяє записати його в `byte b = 5;` лише тому, що `5` входить у діапазон від 0 до 255.

---

## 2. Операції, які ІСНУЮТЬ для цих типів

Для `byte`, `sbyte` і `short` доступні всі стандартні операції, що й для інших чисел:

* **Арифметичні:** Додавання (`+`), віднімання (`-`), множення (`*`), ділення (`/`), остача від ділення (`%`).
* **Порівняння:** `==`, `!=`, `<`, `>`, `<=`, `>=`.
* **Побітові (Bitwise):** І `&`, АБО `|`, виключне АБО `^`, заперечення `~`, зсуви `<<` та `>>`.
* **Інкремент/декремент:** `++` та `--`.

**Проте тут криється головна пастка C#!** Ви можете застосувати ці операції, але результат вас здивує.

---

## 3. Операції, які НЕ ІСНУЮТЬ (або обмежені)

Насправді в C# на рівні мови **не існує арифметичних та побітових операторів, які повертають типи `byte`, `sbyte` або `short**`.

Коли ви виконуєте будь-яку арифметичну чи побітову операцію над цими типами, компілятор застосовує так зване **інтегральне підвищення (integral promotion)**. Він автоматично приводить обидва операнди до типу `int` (або `uint`), і сама операція виконується вже над 32-бітними числами.

### Приклад 1: Арифметика, яка "не працює" напряму

Наступний код **не скомпілюється**:

```csharp
byte a = 10;
byte b = 20;
byte result = a + b; // ПОМИЛКА КОМПІЛЯЦІЇ!

```

> **Чому?** Тому що `a + b` перетворюється на `(int)a + (int)b`. Результат операції має тип `int`. Компілятор забороняє неявно приводити великий `int` (4 байти) до малого `byte` (1 байт), бо це може призвести до втрати даних.
> **Як правильно:** Потрібно робити явне приведення типу:
> `byte result = (byte)(a + b);`

### Приклад 2: Побітове заперечення

```csharp
byte b = 0;          // В бінарному вигляді: 0000 0000
var result = ~b;     // Який тип у result? Сюрприз — це int!
Console.WriteLine(result); // Виведе -1, а не 255

```

> **Чому?** `~b` перетворило `byte` на `int` (усі нулі), а потім інвертувало всі 32 біти, що дало `-1` у комп'ютерній логіці.

### Особливість операцій присвоєння (`+=`, `*=`, `&=` тощо)

А от складені оператори присвоєння працюють без явного кастингу:

```csharp
byte b = 10;
b += 5; // Скомпілюється чудово!

```

Ці оператори мають вбудоване приховане приведення типів. Тобто рядок `b += 5;` компілятор сам розгортає в `b = (byte)(b + 5);`.

---

## Підсумок

1. **Існують:** Усі математичні, логічні та побітові операції.
2. **Не існує:** Можливості отримати результат цих операцій у форматі `byte/short` автоматично. Результат **завжди** підвищується до `int`.
3. **Виняток:** Операції `++`, `--` та складені присвоєння на кшталт `+=` автоматично повертають значення до початкового малого типу.
